# 攸宁 · Youning

[![CI](https://github.com/haotemans/youning/actions/workflows/ci.yml/badge.svg)](https://github.com/haotemans/youning/actions/workflows/ci.yml)

> 从一句回应开始，成为日常里可靠的帮手。

**攸宁（Youning）** 是一个以 Rust 构建的可扩展个人智能助手。它从 QQ 私聊与群聊出发，将对话、记忆、参与判断与工具调用连接起来：在需要时回应，在有事时帮忙，也知道什么时候保持安静。

聊天是入口，而不是边界。攸宁希望逐步走向桌面端与更多平台，让信息整理和日常任务也能自然地融入对话。

项目原名 **云团bot（yuantuanbot）**。「攸宁」是项目名，不要求每个使用者都把自己的助手叫作「云团」；你可以在管理面板中编辑人格，塑造属于自己的交流方式。

> **更名与兼容性**：仓库与项目展示名称已改为 `youning` / 攸宁。当前 Cargo 包、可执行文件、发布产物及默认数据库仍沿用 `yuantuan` 命名，下面的运行命令与文件路径因此保留原名。升级时继续沿用这些名称和既有数据路径。

架构概览见下文；详细行为与验证边界见[上下文与记忆](docs/features/core/memory.md)、[任务调度](docs/features/core/tasks.md)及 [ADR-0012](docs/adr/0012-context-memory-task-runtime.md)。

## 现在能做什么

| 能力 | 说明 |
| --- | --- |
| 私聊与群聊 | 通过 NapCat / OneBot 11 接入 QQ，处理私聊、群聊、@、引用和图片消息。 |
| 对话与记忆 | 一人一份跨会话档案，结合相关人物短画像、群画像、近期对话及按需历史检索回答；资料保留来源、版本与有效状态。 |
| 专属表情包 | 附带去重后的云团 60 张表情、60 个文字标签，首次启动自动导入；默认优先选云团专属，支持按上下文配图及“你自己的呢”的承接。面板可按图包筛选、删除、停用或改分类，重启保留调整。[素材清单](crates/core/assets/cloud-memes/README.md) |
| 有分寸地参与 | 结合群聊热度、当前话题与真实回复归属，自然接话、答疑或调用能力；控制发言占比与间隔，不对每条消息机械作答。 |
| 工具与任务 | 支持搜索、生图、社交媒体解析、群管理与 MCP；多步任务默认 2 并发，可拆分子任务，共享预算，保存检查点与工具回执，并将结果送回原会话。 |
| Web 管理面板 | 管理模型、插件与技能开关，查看画像依据、原始发言、任务步骤和投递状态，支持暂停、继续与取消任务。 |
| 轻量自托管 | Rust 后端、内嵌前端与 SQLite 本地存储，以单二进制部署为基础；实际资源占用取决于配置、负载和启用的外部服务。 |

具体工具能力取决于插件开关、模型与外部服务配置。**功能、源码、测试和实现状态请以[功能对应索引](docs/features/README.md)为入口**；设计目标不等于已经交付，已知差距另见[信息流实现参考](docs/reference/message-flow-rules.md)。

**技术栈**：Rust + Axum + Tokio + SQLx + SQLite；Vue 3 + Vite + TypeScript + Naive UI。

### 识图、人物画像与关系语境

私聊或直接呼叫助手时，可识别当前附图、引用图片、同一人刚发图后的连续提问，以及助手刚回复给此人的库存表情。宿主先下载、校验图片，再把像素交给支持图片输入的 `bot_chat` 模型；地址过期、下载失败或模型不支持时明确标记失败。每轮最多处理三张图片；同会话相同像素复用文字观察，明确纠正单独保留原话和来源，后续优先使用修正后的描述。兼容有界纯文字视觉输出，普通群聊刷图不会自动逐张调用模型。历史图片没有可用地址时不能凭空恢复。
运行图库可追加用户提供的独立表情；云团专属图支持PNG、GIF、JPEG与WebP。GIF发送保留原始动画字节，图库预览使用正确的图片类型，不转成静态PNG。已登记的云团专属原文件可按精确来源确认虚构角色归属并复用文字；陌生图片仍走视觉观察，服务超时不再表述为图片模糊。


图片观察、人物资料与当前会话的互动边共同提供语境，原始发言仍是人物和关系依据。分享者不等于图中人物，截图昵称、OCR 和外貌不能证明现实身份、稳定性格或亲密关系。人物事实须有本人原话；多次互动形成的归纳单独标注、保留依据并允许修正。关系图点击人物后按需查看同一人物的资料、图片观察和互动依据。

## Agent 架构

攸宁当前采用 **自研 Rust 运行时 + 事件驱动 + 三角色模型分工 + 对话／任务双路径**。模型负责理解意图、生成内容和选择下一步；宿主代码负责上下文、动作校验、能力调用、执行预算与状态落库，而不是让一个模型直接包办整个系统。

这里的「三角色」是同一运行时中的三种模型职责，可以分别绑定 provider 和 model，并不要求使用三个不同模型，也不是三个互相聊天的独立 Agent。对话路径面向即时交流与技能调用，任务路径面向需要多轮工具执行的工作。

### 整体链路

```mermaid
flowchart TD
    Input["QQ 私聊 / 群聊"] --> Pipeline["接入、会话调度与 Prefilter"]
    Pipeline -->|普通群聊| Poll["每 30 秒读取 SQLite 新增消息"]
    Pipeline -->|@ / 私聊 / 直接呼叫| Direct["即时队列"]
    Poll --> Batch["有界批次：保留作者与原话"]
    Batch --> Context["固定回复锚点与上下文快照"]
    Direct --> Context
    Memory["SQLite：原始记录、画像与群聊记忆"] -->|按来源范围读取| Context
    Context --> Decision["Decision：对象、意图、路线与预算"]
    Decision -->|回复| Chat["Chat：对话与结果分析"]
    Chat -->|结构化执行需求| Decision
    Decision -->|校验后调用| Skills["技能与插件"]
    Skills -->|查询结果| Chat
    Skills -->|正文与附件| Reply["ReplyEngine / 任务结果 outbox"]
    Decision -->|多步任务| Scheduler["持久任务调度：默认 2 并发"]
    Scheduler --> Agent["Agent：执行、等待与汇总"]
    Agent -->|有限子任务| Scheduler
    Agent --> Tools["本地 / 插件 / MCP 工具"]
    Tools -->|实际结果| Agent
    Agent -->|完成或需要补充的事件| Decision
    Agent -->|检查点与调用回执| State["SQLite：任务、预算与投递状态"]
    Chat --> Reply
    Reply -->|投递原会话| Delivery["QQ 消息与附件"]
    Reply -->|实际已发送记录| Memory
    Nightly["夜间增量整理"] --> Memory
    WebUI["WebUI：画像依据、技能与任务控制"] -.-> State
    WebUI -.-> Memory
```

图中展示语义对话与任务循环：Chat 发现需要执行能力时，把结构化需求交回 Decision；Agent 在已确定的目标与权限范围内推进，完成或缺少信息时再返回。普通插话不会自动修改已有任务，等待中的任务也不会反复调用模型检查进度。

插件命令与确定性消息匹配器仍可直接执行。Decision 分流的信息查询技能在返回无附件结果后交给 Chat 分析；直接命令和其他插件结果可沿原有正文、附件发送路径交付。普通回复走会话发送队列，任务结果另有持久化 outbox。

### 三种模型角色

| 角色 | 负责什么 | 输出交给谁 |
| --- | --- | --- |
| `decision` | 判断回应谁、意图与缺失信息，选择回复、追问、检索、技能或任务路线，并为任务分配预算。 | 输出结构化 JSON；宿主校验消息依据、归属、参数和权限后分发。 |
| `bot_chat` | 根据人格与当前上下文交流，分析搜索或任务结果；发现执行需求时可请求重新路由。 | 聊天正文交给回复引擎，结构化执行需求交回 Decision。 |
| `agent_exec` | 围绕明确目标调用工具、拆分有限子任务、读取结果并汇总；缺少信息时等待补充。 | 输出 `tool_call / reply / done / delegate / wait_input`，由调度器执行、记账和落库。 |

三者通过 [LlmGateway](crates/core/src/llm.rs) 使用统一的模型调用入口，角色绑定保存在 `providers.toml`。角色是职责分工，不与某个模型品牌绑定；例如每日归纳也复用 `decision` 角色。当前 Agent 执行采用应用层 JSON 动作协议，由 Rust 查表调用工具，不依赖模型直接执行代码。

### 对话管线：先判断，再回应

[Bot 管线](crates/core/src/bot.rs) 先保存消息，再分两条入口：普通群聊每 **30 秒**从 SQLite 读取新增未处理消息，没有新增消息就不调用模型；**@、私聊、直接呼叫和有效承接**走即时队列，不等待定时器。同一会话的普通批次最多一个在运行，即时队列独立处理；不同会话按会话类型与编号隔离。`Prefilter` 保留自身、其他机器人过滤及发言节流。

每批最多 40 条、消息 JSON 最多 10,000 字符，按未读顺序取连续前缀，超出部分留待下一轮。Decision 阅读整个批次后选择一个真实作者的消息作为回应对象，不再固定回应第一条；随后 Chat 加载该对象的短画像与同一上界内的会话语境。单条长文保留明确的 2,000 字符摘录标记，全文仍在数据库。

[Decision](crates/core/src/decision.rs) 给出动作建议后，宿主继续检查请求原话、当前会话可用的技能、可见消息依据、对话对象和参与冷却。模型的建议不等于最终执行指令；不满足约束时可以收紧为澄清、说明不确定或忽略。输出格式不合法时重试一次；仍失败则不执行动作，每条消息最多累计失败 3 次（首次及最多两次自动重试，间隔 30、60 秒），达到上限后显示停止原因。明确的模型配置/权限错误立即停止，该网关不再提交 Decision 请求，重新保存模型服务配置后才解除。待处理消息超过 10 分钟停止自动补答，原文继续留在记忆来源中。成功忽略属于完成判断，调用失败不冒充读完。模型推理中断可以恢复；已进入执行但结果不明的消息标为 `uncertain`，不自动重放插件或付费操作。详细规则见[语义参与决策框架](docs/reference/decision-framework.md)。

表情支持单独回应和文字附图，Decision可选择类别与图包，Chat也可在回复中使用真实表情指令。云团专属与其他图库分开，默认优先自己的；只有明确要求新画面才走生图。实际发送成功后保存表情身份和回复锚点，后续不会只看到“图片”。连续两轮纯文字时提示模型考虑合适配图，普通配图默认间隔至少30秒、每会话5分钟最多4张；明确索取库存表情独立校验，不被这一间隔挡住。详见[表情功能](docs/features/core/memes.md)。

公开群聊可选择“自然接话”：分享、共情、玩梗和共同话题的承接不必等待@，也不要求提供新知识或符合云团的兴趣。宿主结合近2分钟人类消息量、参与人数、近期趋势和云团已发轮数控制节奏；渐热群默认90秒、活跃群45秒，过密或云团占比过高时放慢。接话限一泡、最多240字，不因此调用生图、搜索或安排任务。指定给他人的话与明确收尾仍保留边界。引用群友原文再@云团要求改写或分析时，引用作为素材，协议确认的@及云团QQ身份映射优先，不把引用作者误当请求对象。[参与策略与完整阈值](docs/reference/decision-framework.md)有单独说明。

管理面板的「决策追踪」可查看待判断、已领取、执行中及待核实消息，并显示每次判断的入口、批次大小、实际作者和消息锚点，以及停止重试的原因；新记录还显示群聊热度、参与人数、间隔和自然接话模式。纯保持安静不需要虚构回应对象或补调模型。「运行参数」同步展示后端当前的30秒周期与即时入口，待核实动作不会因查看页面而重试。

普通回答、技能结果和表情最终汇入回复引擎。**日常聊天不需要每次启动一个多轮 Agent 任务**，明确需要工具循环的请求才进入 `start_task` 路径。

### 上下文与记忆：按需读取，保留依据

[Context Builder](crates/core/src/context_builder.rs) 在数据库一致性读取中固定本轮回复锚点、引用和消息上界。Decision 与 Chat 使用同一份事实快照，等待模型期间的新消息不会悄悄改变本轮回复对象。

每轮加载当前发言者、被引用或真实 @ 对象的可见短画像，以及当前群画像和近期连续对话。只有 Decision 提出历史检索需求时，才补充当前会话近 30 天内的相关原文，最多返回 6 条。**30 天是检索范围，不是每轮注入量，也不是长期记忆的删除期限。** 消息以 JSON 保留说话人、时间、@ 和回复关系；云团实际发出的消息用于对话衔接，不自动成为关于别人的事实证据。

长期存储使用 SQLite，供模型读取的资料按本轮需要组装为 JSON：

| 资料层 | 保存什么 |
| --- | --- |
| 原始记录 | 群聊、私聊、云团实际发送的消息及图片观察，保留真实归属和时间。 |
| 事实与事件 | 带原消息依据的事实、计划与进展，可标记当前、已结束、待确认、被修正或已过期。 |
| 人物与群画像 | 同一人跨群、私聊共用一个身份与档案；群画像记录有依据的群内话题、习惯与梗。具体资料仍遵守来源范围，私聊来源不带入群回复。 |
| 日记与版本 | 会话日记、每日概览和画像变化历史，可在面板追溯依据，旧群聊记忆和摘要继续保留。 |

[夜间整理](crates/core/src/consolidation.rs) 默认北京时间 **03:00** 开始，群聊记忆与人物画像分配独立额度；人物画像每晚最多 **10 人**，串行处理、每人完成后间隔 **60 秒**。优先兼顾长期未整理者和有新事实线索者，结果与增量进度一起提交，失败不消费尚未处理的消息。

上下文使用带数据库、来源范围和版本信息的材料缓存；画像或依据被修改、删除时使缓存失效。稳定指令与技能目录保持确定顺序，动态消息后置，以利于供应商复用公共前缀。供应商提供的缓存命中数据可记录，缺失时保持未知，不承诺命中率。

普通回复使用较小预算；**300k 是保守估算上限**，当前按 UTF-8 字节估算并预留输出空间，还没有精确 tokenizer 或供应商模型上下文能力自动识别。历史检索仍是有界词项匹配，没有引入向量数据库。详细行为与边界见[记忆功能](docs/features/core/memory.md)。

### 能力扩展：Tool、Skill、Plugin 与 MCP

| 扩展层 | 当前实现与职责 |
| --- | --- |
| **Tool** | 最小执行能力，提供名称、描述、参数 schema 和调用接口；由 [ToolRegistry](crates/core/src/tools.rs) 统一注册。Agent 从注册表获取工具目录并执行。 |
| **Skill** | 可封装提示词、模型调用或工具逻辑，由 [SkillRegistry](crates/core/src/skills.rs) 管理。SQLite 同步能力说明、参数元数据、启停、会话范围和调用记录；实际执行仍须有已加载的插件实现并通过权限检查。支持 Decision 选择及命令／消息匹配直派。 |
| **Plugin** | 打包与管理 Tool、Skill 的工程单元，通过 `plugin-api` 接入宿主。当前是编译进程序的 Rust 插件，运行时可启停和调整配置；宿主约束会话范围、超时、并发与输出大小，见[插件宿主](crates/core/src/plugins.rs)。 |
| **MCP** | 通过本地子进程的 stdio 连接外部服务，将发现的工具包装后接入同一 ToolRegistry；当前实现覆盖工具发现与调用所需的子集，见 [MCP 客户端](crates/core/src/mcp.rs)。 |

Docker 开发沙箱是可选工具能力，默认关闭，配置见[开发沙箱指南](docs/reference/agent-sandbox.md)。它不意味着所有原生插件和 MCP 子进程都自动运行在沙箱中；这些扩展仍应按受信任代码配置和使用。

### 任务执行：共享预算、检查点与投递回执

[Agent 执行器](crates/core/src/agent.rs) 先保存任务的原始发起人、会话、目标、消息锚点和版本，再由数据库队列调度。事件只负责唤醒；丢失唤醒通知不会丢掉持久任务。

默认 **2 个执行槽位**，父子任务共享。Agent 可按需拆分有限子任务，父任务等待时释放槽位，待子任务结束后汇总。Decision／Router 为根任务分配调用次数、时间和累计上下文预算，运行时执行硬上限；缺省预算为 10 次模型调用、300000 保守估算额度和 900 秒，子任务与重启不会重置消耗。单工具最多等待 120 秒，同时受任务剩余时间限制。

执行前登记工具调用，实际结果与下一检查点一起提交。恢复时先读取已有回执；同根任务不能通过换版本或拆子任务重复执行相同参数的动作。连续无进展、输出解析失败、工具错误、超时或预算耗尽会停止自动循环。长执行历史按阶段保留原目标、回执索引和近期记录，完整结果继续保存在 SQLite。

新消息先区分闲聊、问进度、补充、修改、暂停、取消或独立任务。控制已有任务需核对发起人、会话和原话；管理面板提供受管理员认证保护的暂停、继续与取消入口。任务版本阻止迟到结果继续推动已修改或取消的任务，已经开始的外部动作则不能保证撤销。

**任务完成与消息送达分别记账。** 根任务完成或需要补充时，经 Decision 与 Chat 组织回复，将正文和当前版本产物写入持久 outbox，再发送到原会话。面板可区分执行中、等待补充、等待子任务、已完成及投递状态；适配层返回消息编号后才记为已发送，这不等于群成员已阅读。

有完整检查点且没有未确认外部动作时，可以继续未完成步骤。工具已开始但缺少完成回执，或发送结果不确定时，停止自动重放并保留待核实记录；当前尚未提供通用的外部动作自动核实与人工核实后恢复界面。详细协议、限制和测试入口见[任务功能](docs/features/core/tasks.md)。

### 运行支撑与源码入口

主进程在 [main.rs](crates/yuantuan/src/main.rs) 中装配对话管线、任务执行器、插件、MCP、每日归纳和 WebUI。SQLite 保存业务状态与任务流水；[EventBus](crates/core/src/event.rs) 使用进程内 `tokio::broadcast` 解耦模块，Tracer 与面板用于观测。事件总线不是持久消息队列，观测事件可能因消费滞后而丢失，不能用 Trace 代替任务数据库判断是否完成。

本节与 [ADR-0012](docs/adr/0012-context-memory-task-runtime.md) 及[功能主文档](docs/features/README.md)保持对应。自动化测试覆盖 mock 模型、SQLite 状态与浏览器交互；真实模型归纳质量、QQ 媒体投递和部署配置仍需在目标环境验收。后续设计与当前实现边界分别记录在 [docs/README.md](docs/README.md) 的对应入口。

## 快速开始

### 准备条件

QQ 接入需要一个已能正常登录的 NapCat 实例；对话与任务执行需要配置可用的 LLM provider。当前 QQ 接入采用 **OneBot 11 反向 WebSocket**：攸宁监听，NapCat 主动连接。

从源码构建还需要 **Rust stable** 与 **Node.js 24 + npm**，与仓库 CI 的工具链选择保持一致。Node.js 仅用于前端构建。

### 方式一：下载二进制

不想本地编译，可以到 [Releases](https://github.com/haotemans/youning/releases) 查看发布包。CI 会在 `v*` tag 构建成功后发布；普通分支提交的构建产物可在 [Actions](https://github.com/haotemans/youning/actions/workflows/ci.yml) 对应运行的 Artifacts 中获取。

| 平台 | 发布产物 |
| --- | --- |
| Linux x86_64 | `yuantuan-linux-x86_64`，musl 构建，附同名 `.sha256` 校验和文件。 |
| Windows x86_64 | `yuantuan-windows-x86_64.zip`，解压后运行 `yuantuan.exe`。 |

Linux：

```bash
chmod +x yuantuan-linux-x86_64
./yuantuan-linux-x86_64
```

Windows PowerShell（在解压目录中）：

```powershell
.\yuantuan.exe
```

前端已嵌入发布二进制。配置文件缺失时，首次运行会生成 `config.toml` / `providers.toml` 模板；生成模板不等于已经完成模型和 QQ 接入配置，请继续下面的配置步骤。

### 方式二：从源码构建

```bash
git clone https://github.com/haotemans/youning.git
cd youning

# 构建前端，产物将嵌入 Rust 二进制
cd webui-frontend
npm ci
npm run build
cd ..

# 启动后端；当前 Cargo 包名仍为 yuantuan
cargo run --locked -p yuantuan
```

前端产物写入 `crates/webui/static/` 并随仓库保留，因此也可以使用已有产物直接构建后端；修改前端后需要重新构建前端，再构建 Rust 二进制。缺少完整前端产物时，内嵌的 `static/legacy-index.html` 仅作为占位兜底。

### 完成配置与 QQ 连接

配置和数据文件以运行时的工作目录为基准。首次准备配置时，先停止攸宁，检查以下内容，再重新启动：

| 文件 | 用途与注意事项 |
| --- | --- |
| `config.toml` | 主配置，包括 NapCat 监听地址与 Token、WebUI 端口、数据目录、参与节流、每日归纳及表情设置。请按自己的环境设置 `[security].super_admin_qq`，不要沿用仓库中的管理员 QQ。 |
| `providers.toml` | LLM providers 与角色绑定。密钥可通过 `api_key_env` 引用环境变量；不要把真实 API 密钥提交到仓库。 |
| `data/` | 默认运行数据目录，包含 `yuantuan.db`、表情、任务产物与日志等；可通过 `[data].dir` 调整。 |

从源码运行时，仓库中已有的配置同样需要检查。请为 `[napcat].token` 设置自己的随机 Token，不要沿用示例值。

1. **启动攸宁**，确认正在监听配置中的反向 WebSocket 地址，默认是 `ws://127.0.0.1:6199/ws`。
2. **在 NapCat WebUI 中添加连接**：进入「网络配置」，新建 **Websockets 客户端**，名称可填「攸宁」，URL 填 `ws://127.0.0.1:6199/ws`，Token 与 `config.toml` 中 `[napcat].token` 保持一致，启用并保存。
3. **打开管理面板**：访问 `http://127.0.0.1:8085/`，首次登录时设置管理员密码，再到「配置 / 模型」页配置 providers，并绑定 `decision`、`bot_chat`、`agent_exec` 角色。
4. **检查连接与模型状态**：日志出现 `NapCat WS 已连接` 和 `get_login_info 完成 self_qq=...` 表示 QQ 链路已建立；模型角色尚未配置时，不能据此认为助手已经可以正常回复。

上述 `127.0.0.1` 地址适用于两个进程处于同一主机网络环境的情况。NapCat 位于容器或另一台机器时，需要改为它实际可访问的地址，并同步检查攸宁的监听地址与防火墙；部署配置可参考 [deploy/compose.yml](deploy/compose.yml)。

## 地址与端口速查

| 用途 | 地址 / 端口 | 说明 |
| --- | --- | --- |
| 管理面板 | `http://127.0.0.1:8085/` | 攸宁提供，首次登录设置管理员密码。 |
| 后端 API 与事件推送 | `http://127.0.0.1:8085/api/*`、`ws://127.0.0.1:8085/ws` | 与管理面板同源。 |
| NapCat 反向 WebSocket | `ws://127.0.0.1:6199/ws` | 攸宁监听，NapCat 的 Websockets 客户端主动连接。 |
| NapCat WebUI | `http://127.0.0.1:6099/webui` | NapCat 自身的管理面板，以实际部署配置为准。 |
| 前端开发服务 | `http://127.0.0.1:5173/` | 在 `webui-frontend/` 中执行 `npm run dev`，仅用于前端开发。 |

管理面板和 OneBot 接口不要直接暴露到公网。需要远程访问时，使用受控网络或带 TLS 与访问控制的反向代理，并在开放访问前完成管理员密码和 Token 配置。插件、MCP 与开发沙箱可能访问外部服务或执行操作，仅启用你信任且确有需要的能力。

更新攸宁服务时应保留现有数据库、配置、插件状态和 NapCat 登录数据；不要为了更新攸宁而顺带重建或重启 NapCat。

### 忘记管理员密码

先停止攸宁，备份实际数据目录，再仅清除管理员密码哈希：

```bash
sqlite3 data/yuantuan.db "DELETE FROM state_kv WHERE key='admin_pass_hash';"
```

上述路径适用于默认数据目录；修改过 `[data].dir` 时请使用对应路径。重启后，在本机重新设置管理员密码。此操作不删除聊天与任务数据，**不要通过删除整个 `data/` 目录来重置密码**。
