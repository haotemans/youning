# 群聊识图与表情包能力：实施状态与后续接入点

## 本分支已实现：表情包手动添加
- 管理员在 WebUI「表情图库」中多选 PNG/JPEG/GIF/WebP 上传，可以指定分类（默认 misc），直接成为 active。
- 每张图片上限 10 MiB，服务端验证文件签名及解码，文件名由 MD5 生成，使用现有 dHash/MD5 去重机制。
- 上传进入 data/memes/_manual/，文件、图库 SQLite 记录与现有发图管线共用，保留动画原文件。
- POST /api/memes/upload?category=开心 为管理员 session 认证接口，请求正文为原始图片字节。
- 文件传输采用同源管理 API；反向代理须允许 10 MiB 请求体（实际限制需考虑代理开销）。

## 已发现的缺口（本分支尚未完成）
1. 识图：QQ ingest 已采集 image_urls，但 Decision、BotChat 目前只处理纯文本；须实现独立视觉模型配置，图像只按需进入视觉请求，限制 URL 来源、下载字节量和时效，绝不能将图片直接作为聊天指令。
2. 偷表情包：目前默认对群内每张图片仅抽样 0.5%，无 sticker/普通图片区分；需处理 QQ 图片 subtype / summary / 动图特征及审查流程，并将采样策略按群、类型独立配置。
3. 发送：ReplyEngine 已解析 ::meme 并从 active 库按类别抽取图片；应增加安全的图像消息交付测试，保证模型端能稳定选择该指令，并提供管理面板测试发送操作。
4. 当前图库的重复判定采用 dHash 首帧，对于文字不同、布局相似的表情包可能误伤；建议为表情包采用更保守的感知阈值，并增设人工保留重复选项。
5. 当前发图使用 file:// 绝对路径；需要在 NapCat 不与服务共享文件系统的部署中验证，否则改用 OneBot 支持的可达 URL/base64。
6. 服务器部署应仅更新攸宁服务，保留 NapCat 容器、QQ 登录态及持久化目录。

## 建议验收
- 本地 GIF/JPEG/PNG/WebP 上传成功、动画不被静态化、数据库 active 可查。
- 上传重复、格式伪装、解码失败、超限、非法分类返回明确错误；并发相同内容无误删。
- 登录失效上传拒绝；WebUI 添加后刷新并可预览。
- 下一阶段：群里 @机器人发送图片，模型确实识别并回答；群聊表情自动采样入库后，机器人能按语境发回表情包。
