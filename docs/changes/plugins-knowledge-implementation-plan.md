# 插件与知识库实现草案

日期：2026-10-11。原方案草案；后续用户已确认优先实现编译期 Rust 插件公共接口。

本轮实现：plugin-api、构建清单生成注册、宿主生命周期和调用限制、示例迁移、插件配置面板。接入指南见 ../../plugins/README.md。面板上传/编译部署器、知识库正文导入与检索仍未实现。下文保留最初建议及待办，独立进程建议不代表当前已采用。

## 已确认的现状

- `crates/yuantuan/src/main.rs::load_enabled_plugins` 仅注册编译进程序的 hello 插件。放入新目录不会自动获得新能力。
- `crates/webui/src/plugins_api.rs` 以同名 Tool 判断插件是否加载，并把全局 Tools / Skills 显示在该插件下面，缺少真实归属。
- 插件开关只写 enabled 标记，需要重启；插件数据目录展示与约定的 `data/plugins/<id>` 不一致。
- Tool 与 Skill 注册表只支持注册和查询，缺少卸载、冲突处理和调用生命周期。
- 已有 MCP 工具调用基础，但 stdio 使用 Content-Length 帧；接入通用 MCP 服务前需核对标准传输、握手、超时与退出行为，不能只验证自制测试服务。
- `/api/kb/status` 固定返回 `enabled: false, docs: 0`，没有导入、索引、检索与回复接入。

## 建议的第一版范围

插件默认方案：保留已有 Rust 内置插件，新增插件通过面板管理独立进程，复用并完善 MCP 工具协议。不要引入 Rust 动态库或进程内脚本运行时。

知识库默认方案：先支持手工录入、TXT / Markdown / FAQ；PDF、Word 的提取器作为后续可选能力。SQLite 存文档、分块及索引，默认关闭向量检索和本地模型。

以上是推荐方向，不覆盖用户选择，也不把已有“编译期插件”的历史决定默认为已经变更。

## 1. 插件管理基础

每个插件有稳定 id、版本、能力列表、兼容版本、配置结构、运行状态和最后错误。启用意图与实际运行状态分开存储，面板不能用开关代替运行状态。

能力通过插件 id 命名空间注册，并记录归属。重复名称要报错，不能静默覆盖。停用后立即停止接受新调用；正在进行的调用使用明确的完成或超时策略，然后注销能力、清理进程。进程异常不能拖垮机器人。

第一版应包含：

- 安装本地插件包、查看元信息、填写配置、启停、查看运行日志与调用结果。
- 配置检查失败时保留旧配置；敏感配置不回传明文。
- 每群启用范围、调用超时、并发上限、输出大小上限。
- 执行前由服务端根据 ToolCtx 校验群与调用者，不能信任模型传入的身份。
- 插件数据统一位于 `data/plugins/<id>`，纳入现有备份。
- 安装器限制解包路径；启动参数使用结构化参数数组，不拼接 shell 命令。
- 独立进程提供故障隔离，但不等同于文件和网络权限沙箱；面板不得虚称已经实现权限隔离。

第一版先做本地安装，不引入插件市场、自动下载更新和任意远程仓库安装。

## 2. 知识库检索闭环

数据对象包括知识库、文档、文档版本、分块、索引任务以及作用范围。文档保留标题、来源、更新时间、内容校验值和解析错误。

完整路径：导入 → 有界分块 → 建索引 → 检索试用 → 机器人引用。索引任务放在后台执行，界面展示排队、处理中、可用和失败状态，并能重试。

检索先使用 SQLite FTS5 / BM25，并单独解决中文分词或字符 n-gram 索引。先用真实中文 FAQ 测召回，不能假定默认按空格切词足够。后续如召回效果不足，再引入可选 embedding 与混合排序。

全局知识库与群专属知识库明确分开；检索前在数据库查询中限制作用范围。原文预览、下载和检索接口使用同一权限规则，不能只在提示词中要求“不跨群”。

回复只附带少量相关片段和来源，计入现有回复快照预算。没有命中时明确说明，不能伪造引用；文档里的指令作为资料内容处理，不能改变机器人行为规则。

更新文档先建立新版本索引，再切换可用版本；旧内容不应与新内容混杂。删除后后续检索不能继续返回旧块；进行中的旧快照采用明确的一致性策略。

## 3. 内存与性能边界

- 导入任务串行或低并发；限制单文档字节数、单块大小、返回片段数和总上下文预算。
- 索引落盘，避免常驻完整原文和全部向量。
- 文档解析、MCP 服务按需启动；空闲回收策略应避免频繁启动造成更差延迟。
- 统计云团主进程、插件进程及合计峰值；浏览器与 NapCat 分开列示。
- 40 MiB 是待评估目标，不作为未经测试的保证。分别测空闲、登录、导入、检索、并发调用与故障恢复。

## 4. 实现顺序与验收

1. 修正插件归属和真实状态，完善工具注册/卸载、失败处理及 MCP 协议兼容测试。
2. 做一个真正可用的插件示例：安装、配置、启用、群聊调用、停用、错误展示完整走通。示例结果不能以返回提示词模板冒充任务完成。
3. 实现文本知识库的数据库迁移、导入队列、分块索引、作用范围和检索 API。
4. 完成文档管理与检索试用页面，将片段及来源接入机器人回复快照。
5. 用“群规 / FAQ 问答”贯通验证，并记录内存和耗时；依据实际需求再加 PDF / Word 和向量检索。

必须覆盖的验证：两个插件能力互不混淆；停用即拒绝新调用；超时/崩溃可恢复；两群资料互不可见；更新与删除后检索正确；中文同义提问的召回效果；无命中不伪造引用；导入中断可重试；备份恢复后文档、索引与插件状态一致。
