# 会话调度与消息过滤

[返回功能索引](../README.md) · [返回文档总索引](../../README.md) · [本模块索引](README.md)

**当前状态：已实现（代码入口）**。此判断基于当前 `main` 的代码入口静态核对；真实模型、NapCat 与外部 API 需在目标环境单独验收。

> 普通群聊周期增量读取、定向即时队列、Prefilter、消息恢复与插件确定性直派。

## 实际行为

- 定向识图在 Decision 前生成观察语境；每张图最多40秒，最多3张，一轮总期限125秒，避免多图被旧的30秒总期限提前取消。图片失败时仍保留明确的失败语境，不把猜测当作观察结果。

- 普通群聊落库后等待独立时钟，每30秒读取新增消息；没有待判断消息不调用模型。每个 `(chat_type, chat_id)` 最多运行一个普通批次，不按每条消息重启计时。
- @、私聊、直接呼叫、已识别的回复承接及插件匹配走独立即时队列，普通批次模型缓慢不占住即时 worker。队列容量沿用已有配置，满时保留数据库待处理状态，下一周期补读。
- `Prefilter` 先过滤自身消息、硬规则和节流；命中插件命令或消息匹配器可直接调用 Skill，不必走模型 Decision。
- SQLite 原子领取限制同一消息重复派发。每批最多40条、消息JSON最多10,000字符，取最早未处理前缀，溢出留待后续；单条长文显式截取2,000字符，全文不改。模型读取到的批次成员才可能完成覆盖，不提前把后续消息标为已处理。
- 成功忽略也算判断完成；Decision或快照失败保留有限重试，累计失败最多3次，首次后间隔30秒、60秒；达到上限标记failed并保留停止原因。重启恢复推理中的消息；执行中断则标记uncertain供核实，旧插件命令不自动重放，待处理消息超过10分钟停止自动补答，原文不删除。sender_bot在摄取事务内持久化，恢复扫描不把其他机器人当群友。
- 每周期至多读取64个会话；同一批次固定上下文上界，批次内最多选择一个回应对象。批次判断期间出现新的定向消息或云团回复时，本批已成功判断的主动动作让位并结束，不把旧消息再送进失败重试；普通新聊天不会一直取消批次。已经入队的回复仍保留原锚点。

直接请求与普通群聊周期分开处理，避免刷屏吞掉真实呼叫；保留协议 @ 对象，对发给其他人的追问不主动接话。执行技能仍要求真实呼叫或同一人的有效承接及原话依据。

## 边界

- 消息被接收并不意味着一定回复；最终动作由[参与决策](decision.md)决定。
- 回复目标与插话处理基于固定锚点；详见[消息流规则](../../reference/message-flow-rules.md)。

V12接入有界Chat→Decision再路由、按需历史检索、来源受限人物/群记忆和后台任务回聊。普通外界消息不直接修改任务；明确控制经原话、发起人、会话类型及编号验证。信息查询技能结果进入Chat分析，不直接发送原始搜索输出。

插件命令与自动解析的回归夹具使用各自独立的真实消息编号，覆盖新增来源幂等记录。

异步管线关闭回归等待实际发送完成后再取消，避免把技能函数返回误判为已经投递。

当前调度裁决见[ADR-0013](../../adr/0013-periodic-decisions.md)。回归覆盖时钟触发、空轮不调用、慢批次中@即时处理、超过20条的输入覆盖、不同作者选取、失败不推进、溢出续读及中断执行不重放。测试使用本地模型/协议替身，不能替代真实QQ与模型验收。

普通批次全局最多两个同时进入模型处理，等待槽位不占用数据库连接；即时队列不等待该批次槽。所有模型角色仍共享既有成本闸和总并发许可，因此网络延迟与全局限流仍可导致等待。

普通批次并发与容量常量由后端状态接口共用，供前端只读展示；不增加第二套配置或改变30秒调度行为。

失败与重排分开：队列拥堵只释放领取，不增加模型失败数；新定向消息导致主动回应让位也不算失败。重启保留失败次数并收敛旧版已超限的pending，failed不自动恢复；具体取舍见[ADR-0014](../../adr/0014-bounded-decision-failures.md)。

实时插件直派夹具使用当前摄取时间；1970年等历史时间留给过期原文保留测试，避免将旧输入误充为刚收到的自动解析事件。

普通30秒批次可由Decision选择[自然接话](decision.md)，不新增每消息模型分类或空轮询。`bot/dispatch_tests.rs`增加公开分享/玩梗场景，验证没有@、知识增量或个人兴趣仍可接话，整批只调用一次Decision，热度和实际回复归属进入同一输入；此为mock管线验证，不代表真实模型或QQ送达验收。

单独发表情改为携带原锚点的库存图作业，默认优先云团图包，后续同人承接可定位实际发过的表情。普通文字也可带Decision配图计划，仍使用原周期/即时入口、现有队列和调用次数；库存选择不产生Agent或NAI调用。详细规则归[表情功能](memes.md)。

无模型插件命令回归通过BubbleSent成功事件确认所有交付完成，再独立断言队列关闭；不把Fake传输先写入请求列表当作持久化/回执已经完成，避免短关闭期限与合法SQLite收尾竞争。生产队列与超时保持原行为。

定向图片入口补齐“先图后问”和对已发库存图的回看，保持单轮125秒/最多3张和原有即时、周期分工；周期判断只读取已缓存的图片文字。Decision有据纠正保存后，执行回复前按同一会话与消息上界刷新视觉语境，避免当轮Chat继续复述旧的错误观察。具体来源与缓存契约见[记忆功能](memory.md)。


## 单独@与连续追问

单独@不再无条件绕过上下文：宿主固定当前anchor，关联同一作者、同一会话近5分钟最近一条尚未实际回复的非空发言。忽略过的普通消息仍可成为参考；跨人、跨群/私聊、过期、明确@他人或已经有发送记录的问题不借用。无关联时仅回复“在呢。”；关联请求真实处于deciding/executing时仅说明上一条仍在处理，不新增模型调用或重复执行。其他有参考的@进入既有Decision→Chat，旧文字不替换当前anchor、不充当执行授权。

`dialogue.pending_requests`来自固定快照内当前作者的真实判断/执行状态，最多3项，每项正文160字并标记截断。它可以说明请求尚在处理，不能证明卡死、故障原因或已完成。关联与上下文边界见[记忆功能](memory.md)，普通文字承接策略见[参与判断](decision.md)。

回归：`bot::dispatch_tests::bare_mention_reads_ignored_question_and_does_not_duplicate_inflight_work`与`bot_context::bare_attention_retains_unanswered_same_author_input_without_replacing_the_anchor`复现先提问再补@，属于mock/本地数据库验证，不能作为真实QQ时延证明。
