# ADR-0013：普通群聊周期判断与定向即时入口

日期：2026-11-08。状态：accepted。修订ADR-0007的首消息10秒窗口和ADR-0006后续实现的逐条启动回放；保留固定回复归属与消息持久化原则。

失败重试、无动作目标和未读回应时效部分由[ADR-0014](0014-bounded-decision-failures.md)修订；下文保留原决定。

## 决定

普通群聊每30秒读取SQLite新增未处理消息，无新增消息不调用模型；@、私聊、直接呼叫和有效承接使用独立的即时队列。插件确定性入口与任务结果通知保持原有专门路径，普通定时器不驱动Agent空转。

普通批次按会话类型/编号隔离，固定读取上界，最多40条、消息JSON最多10,000字符；未装入的后续消息留待下一周期。单条长文使用明确标记的2,000字符摘录，原文仍可查。Decision整体阅读、最多选择一个本批消息作为目标，再按该真实作者读取同一上界内的资料，复用既有权限及参与策略。不同人的话不合成为一个人的授权。

批次输入不受最近20条上下文窗口限制，必要JSON不能被静默裁剪。成功判断后才提交覆盖，成功ignore也算完成；推理失败保留待处理状态并按30秒至15分钟退避。即时消息与普通批次共用原子领取状态，避免重复处理，但即时理解普通历史不自动消费它们。

普通批次推理期间出现新的直接呼叫或助手回复时，尚未执行的主动动作留待下一周期结合新语境再判断；普通新消息不取消它。已经入队的回复始终绑定选定的原消息。

重启只修复状态，不逐条调用模型、不按一小时窗口丢弃未读普通消息。推理中的消息可重试；已开始执行而结局不明的消息标记uncertain，不自动重放付费、下载或群管理操作。旧确定性命令保持谨慎不重放。这里不承诺外部动作恰好一次，也没有新增人工核实恢复界面。

## 取舍

- 不采用每条普通消息都调Decision：调用密集，容易漏掉连续补充。
- 不把所有消息都延迟30秒：直接呼叫需要独立即时入口。
- 不把十秒固定首锚点仅改成三十秒：仍会把第一条当唯一回应对象、提前消费其他消息。
- 不注入整月历史：只发送本批、少量连续语境和相关资料，旧记录继续按需检索。

## 实施与验证边界

实际状态与测试入口以[会话调度](../features/core/conversation.md)、[参与判断](../features/core/decision.md)、[存储](../features/core/storage.md)为准。本地协议/模型替身验证不能代表生产模型判断质量或QQ实际送达；本次变更不授权部署服务器。
