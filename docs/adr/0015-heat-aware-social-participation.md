# 根据群聊热度自然接话

Status: accepted

2026-11-08，用户要求云团根据群聊热度参与讨论，不能只等别人叫云团或符合自身兴趣才说话。新增social回复方式，在现有30秒增量Decision里选择可接的公开话题，不增加每消息分类或空闲时模型心跳。语义判断综合参与价值、当前群画像及共同梗；新知识不再是社会性回应的必要条件。

Runtime区分社交接话与工具执行：公开话题可跨成员承接，但不能借别人的对话授权执行；明确@/引用他人、收尾、重复、伪造依据仍不放行。social不产生任务、技能或任务控制，Chat执行需求不回环。@、私聊、真实同人对话承接保持原优先路径。

SQLite一致性快照内统计同群人类消息量、人数、前窗趋势、单人占比、Bot实际已发轮数及上轮之后人类发言；固定上界，排除其他Bot、同号私聊与后到消息。同anchor多泡只算一轮。自然接话采用安静180秒、渐热90秒、活跃45秒、过密90秒的节奏，并限制近期Bot占比与轮数，安静时仅考虑有落点的公开分享；这些是初始代码阈值，未新增面板调参。完整契约集中于[决策框架](../reference/decision-framework.md)。

本决定部分修订[ADR-0009](0009-semantic-participation-policy.md)中“主动参与必须有新知识且排除玩梗”的策略；原答疑冷却与执行约束保留。不采用按热度强制发言、随机刷存在感、每轮额外模型复判或热闹即自动生图。Trace暴露真实热度和限制原因，social正文一泡且最多240字，空输出不额外补调。

验证分层：热度及策略单测、固定快照/隔离集成测试、mock周期Decision与Chat边界、浏览器桌面/窄屏测试；这些不能证明真实模型自然度或QQ交付，需上线后独立观察。不修改数据库Schema、人格、历史记忆或模型绑定。
